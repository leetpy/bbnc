# 芭芭农场 ADB 浏览和礼包领取任务

使用 Python 3 标准库和 Android platform-tools 的 `adb`，无需安装 Python 依赖。
脚本会自动从 PATH、`ANDROID_HOME` / `ANDROID_SDK_ROOT` 和常见 SDK 安装目录查找 adb；
macOS 默认目录 `~/Library/Android/sdk/platform-tools/adb` 也支持，无需先配置 PATH。
自定义位置可设置 `ADB_PATH=/完整路径/adb`（Windows 使用 `adb.exe`）。
脚本在连接设备前会实际解析一段 XML 自检；如果当前 Python 的 expat 模块损坏，
会探测系统内其他 Python，并自动切换到通过检查的解释器，保留全部命令行参数。
若没有可用解释器，启动阶段就会报错，不会先停止或启动手机应用。
动画页面的标准采集失败或持续遗漏节点时，自动使用随仓库附带的只读 UI 采集器
`tools/farmdump.dex`；源码见 `tools/FarmDump.java`。运行时不需要 Java 或额外安装应用。
淘宝支持已验证的浏览任务和礼包领取；支付宝支持「逛好物最高得…肥料」、
「逛／浏览好物立得…肥料」、「搜一搜『车险』」及「逛一逛省钱会场」任务和领奖。

## 使用

1. 手机开启 USB 调试，连接电脑并允许调试。
2. 手机保持解锁，所选应用已登录，首页有「芭芭农场」入口。
3. 在本目录执行：

```sh
adb devices
python3 farm.py --inspect
python3 farm.py
python3 farm.py --app taobao
python3 farm.py --app alipay
```

多设备时指定设备：

```sh
python3 farm.py --serial 10AGAN0F4X007TN
```

`--inspect` 只感知页面，打印识别结果并保存 UI XML，不点击或滑动。
`--app taobao|alipay` 选择应用，默认 `taobao`。重启只针对所选应用；例如支付宝不会强制停止淘宝。
`--navigate-only` 仅执行下述启动和导航步骤，停在任务列表，不做任务。
`--from-current` 复用已经打开的任务列表，不停止应用、不重新进入农场。
`--task-timeout 90` 设置单轮浏览超时；`--logs /path/to/logs` 指定日志目录。
按 Ctrl+C 停止，仍会写入本次汇总。

## 启动和导航

正常执行 `python3 farm.py --app taobao` 时，按以下顺序操作并打印每一步日志：

1. 读取进程列表，检测淘宝主进程或 `com.taobao.taobao:` 子进程；若存在则强制停止，并核验已停止。
2. 启动淘宝。
3. 等待首页 UI 节点的 `text` 或 `content-desc` 为「芭芭农场」，读取其当前位置。
4. 点击入口，等待农场中的「集肥料」按钮出现。
5. 点击「集肥料」，等待「肥料明细」和任务按钮出现，确认任务列表已打开。
6. 开始处理已支持的任务。

页面加载有 45 秒等待上限，入口位置由每次读取的 UI XML 确定，不使用固定坐标。找不到入口时停止并打印原因，不自动搜索或点击其他入口。`--inspect` 不执行重启和导航；不能与 `--navigate-only` 同时使用。

执行 `python3 farm.py --app alipay` 时：检测支付宝进程 → 已运行则强制停止 → 启动支付宝 → 首页找到「芭芭农场」并进入 → 点击「领肥料」→ 确认任务弹窗 → 按当前可见入口处理已支持任务，包括浏览、车险、省钱会场及下表中的首页访问和金豆访问。实机无障碍节点将「领肥料」入口标为「任务列表」，脚本兼容两种名称；通过“做任务集肥料”和“关闭做任务集肥料弹窗”同时出现确认列表已打开。其余支付宝任务不执行；只想打开列表时加 `--navigate-only`。任务缺失或不可定位时跳过，继续下一项。

点击坐标使用 UI 节点中心，并读取 `wm size` 换算到触控坐标。实测支付宝 UI 为 1080×2400，手机触控为 1260×2800，直接使用 UI 数字会点错位置；如系统设置了 Override size，优先使用该尺寸。脚本每次读取页面更新 UI 尺寸，淘宝和支付宝使用各自当前页面的比例。
UI 尺寸以顶层窗口为准，不以所有子节点的最大边界推算；实测淘宝横向轮播的
屏外节点可延伸至 x=41640，而屏幕宽度只有1260。屏外节点不会扩大屏幕尺寸，
也不会被当成可见按钮。

不执行购买、加购、关注、答题、游戏、邀请、开启通知等任务。
完成文案中的“当前页下单”仅是观察信号，脚本不会点击它。

礼包是额外授权的一键领取任务，不需要浏览或返回。按钮即使标记 `clickable=true`，只要文字是“20点可领”等下一时段或“已领取”，就跳过；同样跳过已完成的 `(1/1)`。脚本不会等待到下一领取时间。
礼包不在屏幕内时会在任务列表左侧区域滑动定位，重新读取节点后点击。

## 支付宝“逛好物最高得…”的实测和判断

实测标题为“逛好物最高得1500肥料”，金额可变化；“逛好物立得1000肥料”是另一条
独立支持的任务，不混入此处理器。入口按钮最初为“去逛逛”；首段完成后，农场进度可已是1/1，
按钮则变为“继续逛”，此时仍要检查浏览页，不能仅凭1/1推断后续奖励状态。

浏览页显示“浏览得奖励”“滑动浏览或查看商品得肥料”“每浏览15秒可得1次奖励”。
本次看到每段显示500，连续滑动后从倒计时变为“已领取”，页面自动发放，不需要点击。
暂停时未领取阶段会显示“滑动以计时”；未知状态也保留为未领取，避免把该阶段丢掉后
误判全部完成。只读取奖励面板，不使用商品广告中的“去领取”“下单得肥料”等文案。
顶部存在重复的简版奖励条，程序不把两份显示算成两份奖励。

计时浏览时UI采集和滑动分别推进：采集超过1秒尚未返回，会在核验支付宝仍在前台后
补充一次滑动，避免商品列表变大导致采集耗时10秒以上、计时期间一直停留。
仅对已识别的支付宝分段浏览和单次立得页面启用；普通列表扫描和车险停留不启用。
采集失败、切换应用或连续20秒仍不能取得新页面时停止维持滑动；退出、点击和返回前
先等待采集线程结束。`浏览UI采集完成`日志记录耗时及补充滑动次数。
若采集期间滚动过，现身卡片点击前必须停止维持滑动并同步重读坐标。

分段栏兼容“每浏览…秒可得1次奖励”和新版“当前浏览…秒可得…”提示；
新版只读取与浏览说明同栏、紧邻导航标题的奖励阶段，不把简版顶栏或商品金额重复计入。
农场进度已是1/1且按钮为“继续逛”时，调度器仍会检查一次剩余分段奖励。
分段奖励已领取但返回首次仍读到0/1时，最多再重读5次，每次间隔0.5秒；不重复进入。
仍未更新则保存 `goodies-progress-unmatched-*.xml` 并停止，不仅凭浏览页已领取记为成功。

新版单栏“滑动浏览…秒得肥料 / 金额”和“已获得肥料 / 金额”也支持。浏览时会持续
检查随滚动出现的“奖励现身，点我 / 立即领”卡片；只点击这组成对文案，点击后必须
在同一结构位置读到“已得肥料100 / 已领取”才记录100肥料，失败不重复点击。
卡片按结构位置去重，已领取状态不再次点击；已观察到的历史领取也计入10张上限。
计时奖励结束后继续找卡片，最多再滑动30次，连续6次未发现新卡片或达到扫描时间上限
即退出，不推算未发现的奖励。卡片只在实时边界可见且未被遮挡时点击；若 XML
滚动坐标异常则不点击该节点。本次实机已验证首张卡片由“立即领”变为100肥料已领取，
其余卡片确认会在继续滚动、加载商品后出现，未将它们视为已领取。

终态实测为导航标题旁的“今日任务已完成”，此时分段面板会整个消失。程序接受该
明确终态，或面板中所有已观察到的阶段均为“已领取”，连续读取两次确认后返回农场。
再核验进度完成或任务连续两次移除；如列表确实出现待领取按钮，则复用公共领奖核验。
浏览页初次读到的就是完成状态时，返回并跳过，不计为本次成功。
如果计时奖励此前已完成，但本次新领取了现身卡片，则仍保存本次卡片领取结果。

“最高1500”是标题标注的上限，不是实际到账总额。仅记录实际读到的阶段金额和状态，
不按上限推算收益。整个任务计一个完成轮次，分段证据存放于 `reward_stages`（最后一次
面板快照）、`new_rewards`、`claimed_before`、`claimed_after`、`completion`。
卡片奖励单独记录于 `new_card_rewards`、`card_claims`、`card_reward_amount`，
扫描停止原因记录为 `cards_stop_reason`；只有本次实际核验的卡片才增加奖励金额。
已有进度1/1且本次未观察到新增奖励时也不重复计入成功。

本次实机探索确认了一段500“已领取”，随后农场显示1/1、继续逛；重新进入显示
“今日任务已完成”。整合后的处理器已实测正常返回并跳过，日志位于
`logs/goodies-verified-20261107-154349/`，没有把人工探索领取的奖励记作代码本次成功。
实机脱敏夹具为 `tests/fixtures/goodies-*.xml`。浏览页奖励识别只使用 XML；
macOS 的任务列表坐标另用本机截图核验，见“支付宝列表坐标兼容”。

## 支付宝“看精选商品得肥料”的执行

任务单独识别为 `featured`，与淘宝推荐商品及支付宝“逛好物最高得…”分开记进度。
实测列表起始0/3，进入后使用同类分段面板；支持计时标签切换为“已领取全部奖励”，
但仍须逐段显示“已领取”并连续两次确认，不能只凭标题上的“最高2000”判断收益。
返回农场后重新读取任务，进度增加才记录本轮并继续；未增加时重读两次，仍无变化则停止，
不重复点击这轮入口。只有最后一次可使用连续两次确认任务移除的完成依据。
若最终出现“领取”按钮，则点击并核验已领取；总次数和剩余次数均以实时任务行为准。
本次实机首轮探索确认0/3→1/3，整合后的处理器自动完成1/3→2/3→3/3，
最后一轮返回后连续两次确认任务移除，汇总为 `status: ok`。各轮均实际读到500、1000
两段“已领取”，没有按列表中的最高2000推算收益。

## 支付宝“逛／浏览好物立得…”的实测和判断

本次实际名称为“逛好物立得1000肥料”，进度0/1、按钮“去完成”；也兼容名称前缀
“浏览好物立得”，金额动态识别。此实现只执行已验证的单次任务，不复用分段奖励判定。

1. 进入独立“浏览得肥料”页面，XML 横幅为“浏览15s得1000肥料”，专属浮标为
   “1000肥料／滑动浏览15秒／得肥料”。任务标题、横幅与浮标金额必须一致。
2. 仅滑动，不点击商品、搜索、下单或其他广告按钮。实测浮标从14、10、6、2秒
   变为“1000肥料／已发放”。零秒、浮标消失或商品广告中的“已发放”都不是成功依据。
3. 返回农场，原任务从0/1变为1/1，按钮变成“继续逛”，没有额外领奖步骤。
   如服务端变体显示已完成待领取，则复用公共领奖核验；移除任务时要求两次确认。
   首次读到旧进度时最多再读取5次，每次间隔1秒，不重进任务；仍未完成则保存
   `instant-progress-unmatched-*.xml` 并停止，不能仅凭浏览页“已发放”记为成功。
4. 后续运行看到该单次任务进度已完成就跳过，不再点“继续逛”。这与“最高得”任务
   需要进入检查剩余阶段的处理方式不同；进入页面时奖励就已发放，也不冒充本次新增。

整条任务记一个完成轮次，结果记录 `displayed_amount`、`browse_signals`、
`browse_already_issued` 及返回后的进度和按钮。浮标出现的动画副本不会重复计奖励。
任务缺失或不可定位时继续下一项；浏览超时、金额不一致或返回后进度未完成时保留现场。

实机完整探索 XML 保存于 `logs/alipay-instant-exploration/`；新处理器对已完成任务的
只读重复运行验证位于 `logs/instant-verified-20261107-155938/`，正常跳过且本次新增数为0。
完整自动流程使用 `tests/fixtures/instant-*.xml` 做回放回归；人工探索取得的奖励没有
计入程序本次成功。浏览浮标识别仅用 Python 标准库与 ADB；任务列表坐标核验见下文。

## 支付宝车险任务的实测和判断

## 支付宝省钱会场的实测和判断

任务列表最初为「逛一逛省钱会场当前进度0，总进度1 完成浏览奖励1000肥料」，同一行按钮是「去完成」。进入「领补贴-支付宝-芭芭农场」页面后，任务说明是「点3个商品，得1000肥料（0/3)」。这里要求点击商品，不是停留一定秒数。

2. 点击一个商品后等待页面变化。普通商品会打开支付宝内的「商品详情」，按返回回到会场；必须重新读到1/3、2/3等进度增加后，才点下一个不同商品。

## 感知 → 决策 → 执行 → 核验

- **感知**：优先 `uiautomator dump --compressed`；持续动画导致 idle 超时或遗漏目标节点时，切换持续无障碍连接导出 XML。macOS 下额外用本机截图文字核验任务列表坐标；浏览页状态仍按 XML 判断。
- **决策**：只匹配明确列出的任务别名，读取 `(当前次数/总次数)`；在标题的最小共同容器中找“去完成”按钮，避免点到其他行。
- **执行**：使用节点实时位置点击。根据 XML 屏幕尺寸滑动，每次滑动后重新读状态；已验证的福利搜索入口仅点击“搜索发现”内可见且可用的词条，不使用个人搜索历史，不点击结果商品或下单按钮。
- **返回**：读取完成文案后按返回键，直到识别到任务列表，最多返回四次。
- **核验**：次数增加才记录成功。最后一次如果任务直接消失，要求已经读到浏览完成文案，并在返回后连续两次确认列表存在而该任务消失。

不能因为没有倒计时就直接判定成功：未加载页面也可能没有倒计时。
商品页使用“当前页下单”等明确文案，普通浏览页使用“任务完成”；返回后进度才是最终核验依据。

UI 采集失败会重试，使用唯一 XML 文件避免误读旧页面。任务未出现或入口始终不可定位时，
记录“跳过任务”并继续下一项，不记为成功；淘宝同一进度本轮不会重复尝试。
浏览超时、金额不一致和未知外部页面等执行异常仍停止，避免在非列表页面继续点击。
支付宝任务已返回后的进度、任务移除或领奖核验失败，会单独记入 `failed_tasks`：
调度器必须重新读取并确认仍在支付宝任务列表，才能继续其他任务；本轮不重试失败任务、
不再次点击其领奖按钮。无法重新确认列表时整轮停止。失败项保存
`task-verification-failed-*.xml`，不会冒充成功，即使后续任务完成，整轮仍标为 `partial`。
正常导航从进入农场前就保持持续无障碍连接；当前页执行模式最迟在滚动前建立连接。
滚动后等待列表节点恢复；单次只读到背景不会立即
判为弹窗已关闭。等待期间不重复滑动或点击，超时会保存 `wait-timeout-*.xml` 并停止，
日志包含该文件路径，便于区分节点遗漏与真正离开列表。
已验证的“昨日施肥奖励可领取”遮挡弹窗只会被关闭，不点击“立即领取”。关闭按钮
必须在该奖励容器内、位于领取按钮下方且唯一匹配，坐标取自实时 XML；弹窗未消失
时不把背后的任务列表判为就绪，也不继续滚动或点击任务。

## 日志和汇总

每次运行创建独立的 `logs/日期-时间-应用/`，日志事件和汇总均记录 `app`：

- `run.log`：终端同样打印的中文操作日志。
- `events.jsonl`：结构化事件，记录任务、进入前次数、完成后次数、总次数、完成依据及实际读到的到账提示。
- `summary.json`：运行状态、错误原因、本次完成轮数及逐轮详情。
- `page.xml`：仅 `--inspect` 模式生成的 UI 层级。

上次已经完成、当前未出现的任务不算本次完成；未读到实际到账金额时不推算肥料总额。日志可能含页面文字，保存在本地。

汇总额外记录 `pending_tasks`（本轮观察到但未完成或待领奖的已支持任务）、
`skipped_tasks`（跳过及原因）、`unsupported_tasks`（未支持或任务行证据不足的标题）。
这些清单仅覆盖本轮实际观察到的任务，不代表账户全部任务。已核验的执行结果会覆盖旧快照进度。
`failed_tasks` 记录核验失败、是否安全继续及现场XML；存在失败项或扫描覆盖未确认时，
`status` 为 `partial`；无法安全继续等致命异常为 `error`。
`scan_coverage.status` 区分 `complete`、`incomplete`、`task_verification_only` 和 `not_scanned`；
`reports` 分别记录调度扫描与任务移除核验的结束原因。

`run_scope.mode` 明确记录 `full`（整轮）、`single_task`（单项）、`verification`（验证）、
`inspect`（只读检查）、`navigate`（导航）或 `scan_only`（仅扫描），并列出指定的 `task_keys`。
直接调用单项处理器会自动标记单项范围；验证脚本应先调用
`runner.set_run_scope("verification", ["instant"])` 等显式声明。单项或验证范围不会执行未声明的任务。
单项和验证成功分别显示 `single_task_ok`、`verification_ok`，只读检查、导航和仅扫描分别为
`inspected`、`navigated`、`scanned`；这些状态都不代表整轮完成。
只有 `full` 范围、整轮覆盖为 `complete` 且无已知待办和失败时，
`all_supported_tasks_complete` 才为 true，正常整轮才显示 `ok`。未支持任务仍单独列出，
不据此宣称全部账户任务完成。进程退出码仍由是否发生致命异常决定。

加入礼包后，`completed_rounds` 为本次所有成功动作的数量，`browse_rounds`、`gift_claims` 分别统计浏览轮次和礼包领取次数。礼包日志额外记录 `button_before`、`button_after`；跳过时也打印按钮文案和原因。

省钱会场整条任务计为一个 `completed_rounds`，三个商品的逐次核验存放在 `product_clicks`；不会把三个点击算成三条已完成任务。

```text
浏览状态 {"state": "done", "signals": ["当前页下单"]}
返回 {"step": 1}
任务完成 {"task": "看严选推荐商品", "before": 4, "after": 5, ...}
本次汇总 {"status": "ok", "completed_rounds": 1, ...}
```

### 逐屏扫描任务

淘宝、支付宝均优先执行当前屏幕可点击的已支持任务。当前屏没有可执行任务时，
滚动一屏并重新读取 UI、匹配所有支持任务；不依赖首屏 XML 包含屏外任务。
每次任务返回后重新匹配。先向列表下方扫描，再反向补扫；每个方向最多滚动
7 次，连续两次滚动后页面文字及位置不变则结束该方向，避免在边界无限滚动。
达到7次保护上限时不会把该方向记为到达边界：扫描结果记为 `limit`，覆盖未确认。
截图OCR没有读到完整任务行时先原地重采集，最多连续3次；期间不滑动、不累计静止次数。
持续识别失败或存在未解决的任务绑定歧义时，结果记为 `recognition_failed`，保存
`scan-incomplete-*.xml`；这些结果都不能用来证明任务已移除。

淘宝和支付宝 WebView 实测会在滚动后继续返回旧的无障碍坐标。macOS 下任务列表额外通过
本机 Vision 识别当前截图，以完整任务标题、进度和同一行右侧按钮确认点击位置；
屏幕上未确认的任务不会按旧坐标点击。截图不会上传，临时图片和识别程序自动清理。
该兜底需要 macOS Vision 和 Command Line Tools（`clang`）；其他平台仍使用 XML 定位。
扫描边界判断同时使用截图文字及位置，避免旧 XML 导致提前结束扫描。
